# EricLoop 当前设备界面密度调整计划

状态：已批准，M15a/M15b 已完成；M15c 尚待后续实施。更新：2026-09-30。关联 [架构设计](architecture.md)、[详细设计](detailed-design.md) 与 [实施进度](implementation.md)。

## 调查依据

指定设备 `10AE970D5P0017U` 的 `wm size` 为 **1260×2800 px**，`wm density` 为物理 560、当前覆盖值 **616 dpi**，系统 `font_scale` 为 **1.12**。按当前显示密度计算，竖屏宽约 **327 dp**，属于紧凑宽度。只按物理像素判断会误以为页面空间很宽；实际 Compose 布局依 dp/sp 与系统缩放。设备设置不由本计划修改。

已从当前已安装版本抓取首页、标签、变更目录、单条 Graph、记录详情和设置的真机截图，保存于本机 `/tmp/ericloop-density-*.png`，未加入公开仓库，也没有为截图修改用户记录。可见问题：共享的 `SectionHeading` 在四个页面使用 32 sp 大标题并叠加英文眉题/说明；首页首条记录接近屏幕下沿；标签双列卡片内部留白较多；详情的大标题、状态卡、操作区将进展列表推到下沿；设置首屏只有两个连接输入项；Graph 的标题区和过滤区占据较多高度。

代码根因集中在 `ui/Design.kt` 的全局字阶（`headlineLarge=32sp`、`bodyLarge=16sp/27sp`），以及 `Records.kt`、`Details.kt`、`Tags.kt`、`History.kt`、`App.kt` 中反复使用的 18–24 dp 页面/卡片内边距、14–20 dp 列表间距。`TopAppBar` 和底部导航仍遵循 Material 组件尺寸，不应与内容卡片一起机械缩放。

参考：[Android Material 3 字号与形状体系](https://developer.android.com/develop/ui/compose/designsystems/material3)、[Android 紧凑宽度定义](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)、[Android 最小 48 dp 触控目标](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)、[dp/sp 与系统字体偏好](https://developer.android.com/design/ui/mobile/guides/layout-and-content/grids-and-units)。官方字阶是可用的层级起点，不要求每个页面都使用最大的 `headlineLarge`；当前问题主要是使用位置和垂直节奏。

## 方案比较与选择

| 方案 | 效果与代价 | 结论 |
| --- | --- | --- |
| 改手机显示大小/字体大小 | 所有应用一起变化，不能只修 EricLoop；会覆盖用户设备偏好。 | 不采用。 |
| 给整个 Compose 树套统一缩放系数 | 改动少，但文字、图标、触控区域一起缩小，容易出现裁切和点按困难。 | 不采用。 |
| 按内容层级设置紧凑字阶、间距和卡片样式 | 可保留输入/点击能力与重点信息；需逐页检查。 | **推荐。** |

本轮优先适配当前 327 dp 竖屏浅色主题。保留 `sp` 对系统字体偏好的响应，不覆盖 `LocalDensity.fontScale`；遵循语义字阶和 8 dp 布局节奏，但细间距可用 4 dp。用户明确不要求本轮调深色主题。

## 目标尺寸与页面调整

下表是**拟定起点**，最终以指定手机截图和文本裁切检查微调。数值为 dp/sp，不是物理像素。

| 元素 | 当前代表值 | 拟定值/规则 |
| --- | --- | --- |
| 首页/子页大标题 | 多处 32 sp | 首页主句 26–28 sp；普通页面标题 22–24 sp；详情记录标题 26–28 sp。避免 TopAppBar 与页面再次出现同级大标题。 |
| 顶栏标题、卡片标题 | 21 sp/多处 `titleLarge` | 顶栏约 20 sp；列表卡片 17–18 sp；次级区块 16–17 sp。 |
| 正文、注释 | 16 sp/27 sp 行高，大量 `bodyLarge` | 阅读正文保留约 16/24 sp；卡片预览与筛选用 14/20 sp；时间/数量用 11–12 sp，保留用户字体缩放。 |
| 页面横向边距 | 20–24 dp | 通常 16 dp；编辑正文等需要聚焦的区域可保持 20 dp。 |
| 卡片内边距与行距 | 16–20 dp、10–20 dp | 主要卡片 12–16 dp，列表间 8–12 dp，内部信息间 4–8 dp。长文本仍自然增高。 |
| 输入框/筛选 | 原生框及部分 52 dp | 搜索采用 46 dp 可见边框、48 dp 布局/点击高度；日期筛选同尺寸但点击后打开日历选择器；类型/状态选择按钮视觉高 36 dp、点击区 48 dp。主要表单自然增高，不裁切输入法、错误提示和浮动标签。 |
| 图标与菜单触控区 | 图标 24–26 dp | 视觉图标可用 20–24 dp；独立按钮触控区不小于 48 dp。 |

实施范围按页面分组：

1. `Design.kt`：整理用于页面标题、卡片、正文和辅助信息的样式；让 `SectionHeading` 有首页与普通页面两种密度，减少重复装饰文字的占位。避免直接把所有 `headlineLarge` 全局改小，以免详情/弹窗产生意外变化。
2. `Records.kt`：缩紧首页概览、已完成入口、列表卡片、筛选区；保持计划浅绿、想法浅蓝、完成金色与可点击卡片。目标是首页无需先滚动即可看到首条记录的主体。
3. `Tags.kt` 与 `History.kt`：按用户后续要求，标签库改为每行三列；默认/自定义卡片图标行同高，自定义编辑按钮保留 48 dp 点击区域，长名称单行省略；底部第三个“变更”入口的记录标题目录采用更紧凑的卡片；Graph 日期筛选改为日历选择器。Graph 节点后续再缩紧，同时继续显示打卡内容和有意义的操作色。
4. `Details.kt`：详情标题、状态、操作区和进展卡片重新排列以减少空隙；保留右上角菜单、完整笔记内容和长文本自然换行。编辑页/打卡弹窗的表单只压缩外围间距与安全的单行字段，不压缩正文阅读区到难输入。
5. `App.kt`：设置页抬高信息密度，所有者、仓库、分支、Token 四个连接字段用同行固定标签与 46 dp 可见边框/48 dp 布局高度；保留明确的 Token 权限、强制上传及恢复确认。顶栏/底栏沿用 Material 组件的基本触控尺寸。

## 实施顺序与验收

执行前先处理当前工作区中尚未提交的上一轮 History/Details/Records UI 改动，确认其编译与真机状态并单独提交，避免本计划与上轮修改混在同一个节点。本计划获批后按“共用字阶与标题 → 首页/列表 → 标签/变更 → 详情/表单/设置 → 全页复核”的顺序逐节点更新 [implementation.md](implementation.md) 并提交。只在当前设备安装；不新增或运行单元测试，不自动推送远端。

同设备、同显示密度和 `font_scale=1.12` 下重新抓六类页面截图，与本次基线比对：

- 首页首条记录的标题及部分正文进入首屏，筛选项和悬浮按钮不遮挡记录。
- 标签目录一屏能完整看到至少两行三列卡片，默认/自定义卡片等高且自定义编辑入口可点；变更目录能清楚显示更多标题，点击区域不小于 48 dp。
- Graph 中日期/操作筛选不裁字；普通节点不重复记录标题，打卡节点的笔记可读；点节点仍能打开完整快照。
- 详情中进展笔记更早进入首屏，长标题/长备注能换行；菜单、编辑、删除确认均可点。
- 设置页首屏能看到更多连接信息；输入框聚焦、键盘弹起、错误提示、中文长文案不重叠。
- 手机保留原有字体/显示设置；仅检查浅色主题。`./gradlew :app:assembleDebug`、指定设备安装、`git diff --check` 通过后提交最终节点。

验收中若任何字段因 1.12 字体缩放而被裁切，应优先调布局和换行，再考虑该元素字号；不通过禁用字体缩放来获得视觉上的紧凑。
