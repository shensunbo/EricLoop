# 变更节点只保存操作后状态

状态：2026-09-30 已实施并在指定手机验证本地迁移与 Graph；云端新版上传未执行。用户确认：点击节点查看该次操作完成后的状态；想比较更早状态时点击更早节点。删除打卡节点只显示删除动作，不展示旧备注。

## 数据与兼容

- 继续保存当前记录、标签、打卡以及按序号排列的事件。新事件只保存 `afterJson`，`beforeJson` 固定为 `null`；这样每个节点仍能展示当次操作完成后的内容，同时不重复保存前一节点已有的完整内容。
- 备份 `schemaVersion` 升为 2。旧版 1 先按旧规则完整验证，再丢弃所有事件中的 `beforeJson` 并转为新版；手机本地数据在启动事务中持久化转换。下载旧云端备份时同样转换，恢复前仍按新版完整校验。
- 正常上传判断内容相同前先比较云端原始格式版本；云端仍为版本 1 时写出新版备份，不把旧 blob 错认作已升级。
- 新版重放以此前节点推导出的状态作为操作前状态，以本节点 `afterJson` 作为操作后状态；保留创建、类型、时间、删除/恢复、标签和打卡归属约束及最终状态一致性检查。恢复前本地安全副本和 GitHub 同步冲突保护不变。

## 页面与验收

- 变更节点弹窗只显示“操作后”内容，不显示“变更前”。删除打卡节点及弹窗只显示删除动作和时间，不再显示旧备注；其他打卡和补记节点继续显示该次操作后的备注与发生时间。
- 更新需求、详细设计、架构与实施进度；应用版本递增。按用户要求不新增或运行单元测试；在指定手机上只读查看已有“网球”或“英语口语”的变更节点、删除打卡节点与设置版本，避免改动真实记录。
- 现有 Git 提交中的旧备份仍含当时的旧快照；本改动只缩小新备份与当前本地事件，若以后要求彻底清除 Git 旧提交中的内容，需要单独制定仓库历史处理方案。
